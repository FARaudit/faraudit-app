**`grep` RETURNS A SILENT ZERO ON FILES WITH NUL BYTES.** Caught live: a Federal Register `.txt`
pulled from `federalregister.gov/documents/full_text/...` contained 9 NUL bytes, so `file` typed it
`data`, grep suppressed all matches, and `grep -n "14026"` printed NOTHING on a document whose

**Why:** a whole evidence table built on one instrument is worth nothing if that instrument can fail
closed — this is the exact failure mode I grade audits F for.
**How to apply:** before trusting any "0 hits" table, run

Then re-run the load-bearing zeros in Python as a second instrument. Here the 3 evidence files were
clean (NUL=0, valid UTF-8) and all 9 AUTO-F zeros re-confirmed SOURCE-ONLY — `52 Each` is 20 in
source / 0 in report. Related: [[reference_write_tool_nul_trap]],
